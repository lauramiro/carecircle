# Hospital Summary Generation – Deterministic Assembly (No LLM)

## Purpose

This document explains why the hospital summary PDF is **not** generated by an LLM. Instead, the backend (`HospitalSummaryService`) assembles data directly from Supabase and renders it into a PDF using a template (`PDFGenerationService`).

## Reasoning

- Patient data is highly sensitive; a rule‑based assembly guarantees **zero hallucination** and **complete determinism**.
- All 8 required sections (patient details, medications, GP contacts, recent care notes, conditions, allergies, flagged patterns, upcoming appointments) are always present – empty sections show "No data recorded".
- No API cost and sub‑3 second generation time.

## Data Sources (Supabase tables)

- `patients` – full name, DOB, conditions, allergies
- `medications` – current active medications
- `gp_contacts` – GP name, phone, email, address
- `handover_journal_entries` – last 7 days of care notes
- `ai_insights` – flagged patterns (if any)
- `appointments` – next 3 upcoming appointments

## Template Variables (used in PDFGenerationService)

| Variable | Source |
|----------|--------|
| `patient.fullName` | patients.full_name |
| `patient.dateOfBirth` | patients.date_of_birth |
| `medications` | array from medications table |
| `gpContacts` | array from gp_contacts |
| `careNotesSummary` | array of journal entries (last 7 days) |
| `conditions` | array from patients.chronic_conditions |
| `allergies` | array from patients.allergies |
| `flaggedPatterns` | array from ai_insights (is_active = true) |
| `upcomingAppointments` | array from appointments (start_time >= now) |

## Future LLM Consideration

If a generative model is later introduced (e.g., to write a narrative summary), this file will be replaced with an actual prompt template. Currently, the deterministic approach is preferred for safety and reliability.
